# **CDGA: Cyclodextrin Guest Analysis Tool**
KNIME workflows for the analysis of cyclodextrin inclusion complexes and guest properties inside the cavity and host characterization.

The GitHub repository contains the CDGA Tool, validation input structures, expected output files, processed molecular structures, Python environment configuration, supporting scripts, and documentation required to install, execute, and verify the CDGA. It is associated with the following paper accepted for publication:
Napiórkowska E, Szeleszczuk Ł. CDGA: A Host-Based Alignment and Descriptor Analysis Tool for Cyclodextrin Inclusion Complexes. Journal of Chemical Information and Modeling, DOI: 10.1021/acs.jcim.6c02866.

The **Cyclodextrin Guest Analysis Align Tool (CDGA Align) - Workflow WITH alignment of cyclodextrin complexes**: aligns all complexes based solely on the host cyclodextrin structure.

The **Cyclodextrin Guest Analysis NoAlign Tool (CDGA NoAlign) - Workflow WITHOUT alignment of cyclodextrin complexes**: uses the original complex coordinates without prior alignment.

Both workflows calculate the guest's position and orientation relative to the cyclodextrin and determine the RMSD relative to a reference complex, defined as the first complex in the tested directory. They contain an appended module for Host Characterization to calculate psi and phi torsion angles for each pyranose and generate XYZ files for Cremer-Pople puckering analysis.

* **`output/`**
  Contains the expected output files generated for the validation dataset. These files can be used to verify the correct execution of the CDGA workflows.

  * **`output/CDGA_Align_output.csv`**
    Output table generated by CDGA Align for the validation MOL files. It contains guest descriptors, atom-mapping results, alignment information, and diagnostic status values.

  * **`output/CDGA_NoAlign_output.csv`**
    Output table generated by CDGA NoAlign for the original validation MOL files. It contains guest descriptors, atom-mapping results, and diagnostic information calculated without structural alignment.

  * **`output/CDGA_NoAlign_output_pf.csv`**
    Output table generated by CDGA NoAlign for structures previously aligned using the field-based alignment method. This file enables comparison between CDGA Align and the external alignment procedure.

  * **`output/CDGA_Tool_processed_molfiles/`**
    Contains the processed MOL files generated by the CDGA workflows.

    * **`output/CDGA_Tool_processed_molfiles/CDGA_Align_molfiles/`**
      Contains MOL files generated after host-based alignment with CDGA Align. These structures can be used for visual inspection of the aligned complexes.
      
    * **`output/CDGA_Tool_processed_molfiles/CDGA_Align_molfiles/Host_characterization/`**
      Contains output files generated by the Host Characterization module, including glycosidic torsion-angle data and pyranose atom coordinates for subsequent host conformational analysis.

      * **`host_torsion_angles.csv`**
        Contains the calculated glycosidic phi and psi torsion angles for the identified pyranose units, together with the atom labels used for each torsion calculation.

      * **XYZ coordinate files**
        Contain ordered pyranose-ring atom coordinates generated for individual complexes. These files can be used for subsequent Cremer-Pople puckering analysis.

    * **`output/CDGA_Tool_processed_molfiles/CDGA_Align_molfiles/matched_atoms/`**
      Contains CSV files reporting the corresponding atom pairs identified between the reference and tested structures during atom-mapping procedures.    

    * **`output/CDGA_Tool_processed_molfiles/CDGA_NoAlign_molfiles/`**
      Contains MOL files processed using CDGA NoAlign without coordinate transformation. Files with the `_pf` suffix correspond to complexes previously aligned using the field-based alignment method.

* **`test_data/`**
  Contains the input MOL files used as the CDGA validation dataset. The structures are used to evaluate geometrical and chemical modifications, guest-atom mapping, descriptor calculations, and workflow execution.

* **`test_data_post_field_aligned/`**
  Contains validation complexes aligned using the field-based alignment method. These structures are used to compare the external alignment procedure with CDGA Align.

* **`environment.yml`**
  Defines the Python environment and required package versions for executing the CDGA workflows.

* **`glide_docking_mol_file_generator.py`**
  Additional Python script used to generate MOL files from Glide molecular-docking results for subsequent CDGA analysis. Only for Maestro Schrodinger package users and with access to Schrodinger Command Prompt.

* **`CDGA_with_host_module_V1_0_0.knwf`**
  KNIME workflow containing the CDGA Align and CDGA NoAlign workflows with Host Characterization appended module and additional PDB file conversion workflow for splitting multiple-frame PDB files and converting them into MOL files. This file can be imported directly into KNIME Analytics Platform.

* **`CDGA_User_Manual_V1.pdf`**
  Detailed user manual containing installation instructions, workflow configuration and execution steps, input requirements, descriptor definitions, output-column descriptions, diagnostic status explanations, and troubleshooting guidance. KNIME workflow containing the CDGA Align and CDGA NoAlign workflows. This file can be imported directly into KNIME Analytics Platform.

* **`README.md` this file**
  Provides an overview of the repository, software requirements, installation instructions, workflow configuration, and basic execution guidance and license information.

* **`alphaCD/`**
  Contains example output files for complexes containing alpha-cyclodextrin as the host.

* **`gammaCD/`**
  Contains example output files for complexes containing gamma-cyclodextrin as the host.

* **`code_to_review_only/`**
  Contains the Python scripts used within the KNIME workflows. These files are provided for code review and reference and are not intended to be executed independently from the configured workflow.

  * **`CDGA_Align_script.py`**
    Python script implementing the CDGA Align analysis, including host-based structural alignment, guest characterization, atom mapping, and output generation.

  * **`CDGA_NoAlign_script.py`**
    Python script implementing the CDGA NoAlign analysis without structural coordinate transformation.

  * **`PDB_Splitter_script.py`**
    Python script used by the PDB conversion workflow to split multiframe PDB files into individual PDB files for subsequent processing.
    
* **`CDGA_demo_videos/`**
  Contains demonstration recordings showing the configuration, execution, and selected workflows of the CDGA Tool. The videos are provided as supplementary documentation to the CDGA User Manual.

  * **`CDGA_Align_and_NoAlign.mp4`**
    Demonstration of the CDGA Align and CDGA NoAlign workflow execution at normal playback speed.

  * **`CDGA_configuration_execution.mp4`**
    Demonstration of CDGA workflow configuration, including Python environment settings and KNIME extension installation, followed by execution of the CDGA Align and CDGA NoAlign workflows at normal playback speed in KNIME Analytics Platform.

  * **`PDB_workflow.mp4`**
    Demonstration of the additional PDB processing workflow used to convert multiframe PDB files into MOL files compatible with the CDGA input format.

### Installation


1. Install the KNIME Analytics Platform from 
   <https://www.knime.com/downloads>

   
2. Open KNIME and install extensions:
   <https://www.knime.com/downloads>

   Menu -> Install extensions-> search for the following extensions:

   	KNIME Base Chemistry Types & Nodes
   	KNIME Python Integration
    RDKit Nodes Feature
    KNIME Chemistry Add-Ons (for additional PDB workflow only)
    Vernalis KNIME Nodes (for additional PDB workflow only)


   and restart the KNIME Analytics Platform after installation

   
4. Install Miniconda from
  <https://www.anaconda.com/download>.
   

Use the default installation settings.


***


### Setting Python environment


1. Open Anaconda Prompt and navigate to the directory containing the **environment.yml** file using the `cd` command.

   example:

   `cd Downloads`

   If the **environment.yml** file is placed in the Downloads directory.

   
2. Set up the Python environment by running the command:

   `conda env create -f environment.yml`

   This command creates the required Python environment and installs all dependencies.
   

3. Activate the environment using the command:



   `conda activate knime-rdkit`


4. Test the environment

   To verify that the required packages were installed correctly, run:

   `conda env list`

   The environment **knime-rdkit** should appear in the list.

   
5. Test whether the required libraries can be imported:

   `python -c "import rdkit, pandas, numpy; print('OK')"`

   If "**OK**" is printed, the libraries were installed correctly.

   
6. Configure Python in KNIME Analytical Platform:

   In KNIME open **Preferences -> Python**:

   Set Python environment configuration to **Conda**. The detected Conda version should appear.

   Select **knime-rdkit** as the Python 3 Conda environment. The associated Python version should be displayed automatically.



Apply and Close.

Restart KNIME after changing the Python environment.

---
Alternative extension installation in KNIME: 
Import the downloaded workflow into KNIME. If KNIME detects missing extensions, install the required extensions according to the instructions described above.
---

### KNIME workflow execution



1. Open KNIME Analytics Platform.
   
2. Import workflows for cyclodextrin complexes from the KNIME Community Hub space:
   <https://hub.knime.com/s/vwhEzWb7MOEgg-dh>
   or open the file CDGA_with_host_module_V1_0_0.knwf.
   
4. Configure and execute the workflows according to the descriptions provided in each node.

   Example input MOL files are provided in the **test\molfiles** directory.
   Expected output tables generated from the **test\_molfiles** are provided in the **output** directory. **Aligned\results.csv** and **non-aligned\results.csv** correspond to the workflows with alignment and without alignment, respectively.

***

### Additional: generating MOL files from the Glide pose viewer file (for Maestro Schrodinger package users and with access to Schrodinger Command Prompt).

1. Open Schrodinger Command Prompt and navigate to the directory containing the pose viewer file example: **glide-dock_name_pv.maegz** file using the `cd` command.

   example:

   `cd Downloads`

   if the **glide-dock_name_pv.maegz** file is in the Downloads directory.


2. Execute the Python script to generate MOL files from the Glide pose viewer file:

   `run glide_docking_mol_file_generator.py glide-dock_name_pv.maegz`

Note:
If the script and input file are not located in the same directory, specify the full file paths accordingly, for example:

   `run C:\path_to\glide_docking_mol_file_generator.py C:\path_to\glide-dock_name_pv.maegz`

   The script generates MOL files named by Entry ID and pose number. The first line of each MOL file contains the Entry ID and the Glide G-score formatted to three decimal places and the pose number.
